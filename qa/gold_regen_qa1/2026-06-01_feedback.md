## Report-level defects

1. **§11 monthly pivots are computed from the wrong month, then falsely marked "CORROBORATED" in §19.**
   The report states the monthly pivots are "from April H 4,889.70 / L 4,500.85 / C 4,614.95." The
   month that should anchor D=2026-06-01's monthly pivots is the last completed calendar month, which
   is May (level file `m_full_period` = 2026-05), not April. Rule violated: framework row 1.2
   (coverage/currency consistency — every date used must be D-1 or earlier and drawn from the correct
   period) and row 5.4 (no synthesised/uncited figure presented as sourced — no citation for the April
   H/L/C appears anywhere in §4 or §13). A compliant monthly pivot table must be built from H=4,773.37,
   L=4,366.35, C=4,539.99 (the May H/L/C implied by the level file's `m_full_P/R1/S1` back-solve), giving
   P=4,559.90, R1=4,753.46, S1=4,346.44, R2=4,966.92, S2=4,152.88, R3=5,160.48, S3=3,939.42 — every one
   of the report's printed monthly levels differs from these by $65–130, all beyond the 0.115×ATR14
   (≈$11.8) Category-3 failure threshold.

2. **§11 weekly pivots are built on a prior-week H/L that does not match the level file, but this is
   correctly flagged indicative** — no separate action needed beyond what §19 already does, except note
   the size for the record: the level-file-implied actual weekly H/L is 4,595.21 / 4,366.35 (back-solved
   from `w_full_R1`/`w_full_S1`), against the report's assumed 4,760/4,400 — every weekly level in §11 is
   off by $33–230. Because §19 already labels the weekly tier single-source-indicative and Card 2
   (below) already carries that caveat, this is recorded as a discrepancy, not scored as a fresh
   restriction breach.

3. **ATR14 is never printed as a number anywhere in the report body.** Rule 3.3 requires "ATR(14)
   stated." The report invokes ATR only conceptually ("3×ATR(14) price cap"). A compliant report states
   the number explicitly, e.g. "ATR14 (full) ≈ 102.6" (level file `atr14_full` = 102.605), and shows it
   being used in the stop/TP/wide-stop-flag calculations on each card.

4. **§13c/d merges the "previous" and "upcoming" calendar into one undifferentiated block** instead of
   the two labelled subsections the structure spec calls for (§2.1). Split into a labelled 13c (prior
   calendar) and 13d (upcoming calendar) on regeneration.

5. **§6's scorecard table omits the required Source A / Source B columns**, giving sourcing only as
   prose above the table. Add two columns to the Date/O/H/L/C/RSI2/Validation table naming the two
   corroborating sources per row (e.g. Investing.com / Bloomberg for the close cells).

6. **No card states a clock time for its entry**, so the anchor override disclosed in §2/§20 is never
   carried onto the cards themselves, as the M1 anchor-override rule requires ("the same converted time
   on the card"). Add the anchor time (e.g. "02:00 broker") to each of the three §21b card tables.

7. **§13d's event collisions (1 Jun Powell/PMI, 2 Jun JOLTS, 3 Jun ADP/Services PMI/Beige Book, 5 Jun
   NFP) are discussed at report level but never appear as a caveat inside any of the three §21b cards.**
   Rule 5.3 requires event collisions to be carried into card caveats. Add one line per card, e.g. "Entry
   window overlaps 1 Jun Powell/PMI — expect elevated intraday volatility before fill."

## Card-level defects (Category 4 / M5 construction rules)

8. **Trade 1 (tactical long) — stop has no ATR buffer beyond the nearest S/R level.** Rule: "Stop =
   tighter of (5-day swing extreme, nearest S/R) + 0.25×ATR buffer." The tighter reference here is the
   daily S1 (report's own §11 value 4,486.86, or the level file's `d_full_S1` = 4,487.6567); the printed
   stop of $4,486 sits essentially *at* S1 with no buffer subtracted. A compliant stop must be at or
   below S1 − 0.25×ATR14(full) = 4,487.66 − 25.65 ≈ **$4,462.0** (using the level file's S1 and ATR14).

9. **Trade 2 (regime-aware pivot, RANGE-type limit) — TP1 is not at entry ± 1R.** Rule: "TP1 = entry ±
   1R … for Trade 1 and RANGE Trade 2." Entry is $4,505, stop is $4,460, so R = $45. TP1 must equal
   entry + 1R = 4,505 + 45 = **$4,550**. The report states TP1 = $4,565, which is entry + 1.33R — a $15
   rule violation. (TP2 at $4,593 is close to the required entry + 2R = $4,595, within rounding.)

10. **Trade 3 ("fork 3B: range/breakout") does not match either the 3B or the 3C construction rule.**
    Rule 3B (range): "limits at 11.4–21.4% / 78.6–88.6% of the 25-day range." Using the level file's
    `swing_low_25d_full` (4,366.35) and `swing_high_25d_full` (4,773.37), a compliant 3B entry sits
    between **$4,686.25 and $4,726.95** (the 78.6–88.6% band, long side) and must be a LIMIT order, not
    a stop. Rule 3C (transition): "confirmed close beyond the 25-day boundary by ≥ 0.25×ATR14," which
    would require the boundary (4,773.37) plus 0.25×ATR14(full) (25.65) ≈ **$4,799.0** as the trigger.
    The report's printed entry, $4,596 stop-above-R1, matches neither formula — it is a bare
    breakout-above-daily-R1 construction with no basis in either sub-strategy's rule. On regeneration,
    either rebuild this card as a genuine 3B limit inside the 78.6–88.6% band above, or as a genuine 3C
    stop at ≈$4,799 with a boundary+0.40×width stop and the corresponding TP1/TP2, and label it
    accordingly.

11. **Trade 3's TP2 ($4,668, "monthly P") inherits the wrong monthly pivot from defect 1.** Once the
    monthly pivots are rebuilt from the correct (May) H/L/C, the compliant monthly P is **$4,559.90**,
    not $4,668.50 — TP2 must be re-derived from the corrected value.
