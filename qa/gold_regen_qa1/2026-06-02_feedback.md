## Report-level defects

1. **D−1 (Monday 1 Jun) Low is wrong by more than 2× the Category-3 failure threshold, and it is
   never flagged.** §6/§21b use Low = 4,489.86; the leak-free file gives `prev_low_full` = 4,447.71
   (Δ = 42.15 = 0.42×`atr14_full`, vs. the >0.20×ATR14 failure line). Every source in §6 is marked
   "CORROBORATED" for Monday with only the Close called out as indicative — the Low carries no
   caveat at all, despite being the larger error. **Fix**: either re-verify the Monday low against the
   named sources and correct it to within 0.09×`atr14_full` (≈USD 9, i.e. 4,438.71–4,456.71) of
   4,447.71, or — if the sources genuinely disagree by this much — flag the Low itself as indicative
   in §6/§11/§19, the same way the Close already is.

2. **The Monday Close is also outside tolerance.** §6/§21b use Close = 4,500.92; file
   `prev_close_full` = 4,484.78 (Δ = 16.14, > the 0.115×`atr14_full` ≈ USD 11.5 failure line); vs.
   `prev_close_cash` = 4,481.20 the gap is Δ = 19.72, also a failure — so this is not a
   cash-vs-full basis artefact. A compliant close must land within USD 11.5 of 4,484.78 (or within
   USD 9.4 of 4,481.20 if the report switches to declaring a cash-session basis).

3. **Daily floor pivots inherit the OHLC error and fail tolerance on 5 of 7 levels.** Using
   `d_full_*`: P should be 4,492.79 (report: 4,512.27, Δ19.48, FAIL); R2 should be 4,590.95 (report:
   4,568.44, Δ22.51, FAIL); R3 should be 4,636.02 (report: 4,590.85, Δ45.17, FAIL); S1 should be
   4,439.70 (report: 4,478.51, Δ38.81, FAIL); S2 should be 4,394.63 (report: 4,456.10, Δ61.47, FAIL);
   S3 should be 4,341.54 (report: 4,422.34, Δ80.80, FAIL). Only R1 (file 4,537.86 vs report 4,534.68,
   Δ3.18) is within tolerance. **Fix**: recompute all daily pivots from a corrected D−1 H/L/C
   (`P=(H+L+C)/3`, `R1=2P−L`, `S1=2P−H`, `R2=P+(H−L)`, `S2=P−(H−L)`, `R3=H+2(P−L)`, `S3=L−2(H−P)`) once
   item 1–2 are fixed; the weekly table needs no change — it already reconciles to `w_full_*` within
   ≤USD 0.5 across all 7 levels.

4. **28-May RSI2 does not reproduce from the report's own stated closes — an arithmetic error, not a
   basis difference.** Report states RSI2(28 May) = 100.0. Using the report's own 26/27/28-May closes
   (4,507.51 → 4,458.21 → 4,494.93) and the brief's formula (RS = mean gain ÷ mean loss over 2
   periods): gains = [0, 36.72], losses = [49.30, 0]; mean gain = 18.36, mean loss = 24.65; RS = 0.745;
   RSI2 = 100 − 100/1.745 = 42.7, not 100.0. (42.7 is in fact the value the report shows one row
   earlier, at 27 May — check the RSI2 column for an off-by-one row shift when regenerating §6.)

5. **§11 is missing the monthly floor-pivot table entirely.** The structure spec requires daily,
   weekly **and monthly** pivot tables; §11 provides only daily and weekly, with a stated reason
   (prior-month H/L/C not dual-source corroborated). The reason is transparently disclosed (good for
   Category 5) but the table itself is still a required-section gap (Category 2). **Fix**: either
   source and publish the monthly table, or replace the omission with an explicit "MONTHLY: NOT
   PRODUCED — insufficient corroboration" placeholder row so the section is structurally complete even
   when the content is withheld.

6. **§6's Scorecard columns deviate from spec.** The structure spec calls for separate Source A /
   Source B columns; §6 collapses both into a single "Sources" column (e.g. "Investing × Bloomberg")
   and adds an unlisted "Trend" column. Not a numeric defect, but a format one — restore the two
   separate source columns for the regenerated table.

## Card-level defects (M5 construction rules, `docs/QA_PROTOCOL_TRADE_CARDS.md` / brief §3)

7. **Trade 1 (`2026-06-02_Trade_1`) is built as a conditional STOP/LIMIT order, not a market order.**
   M5 fixes Trade 1 as "market at the daily-open anchor." The card instead reads "Sell stop at 4,488 …
   or sell-limit into 4,535 on a rally" — two conditional branches, neither a market fill at the
   02:00-broker anchor. **Fix**: regenerate Trade 1 as a single MARKET entry at the D−1 close
   (`prev_close_full` = 4,484.78, once corrected — see item 2), with stop/TP derived from that entry,
   not from a break-of-low trigger.

8. **Trade 2 (`2026-06-02_Trade_2`) uses RANGE-regime construction (limit fade at daily R1) while the
   report's own §9 regime call is Transitional.** M5 routes a Transitional regime to "breakout side
   only," not a resistance fade. The card as built contradicts the report's own stated regime.
   **Fix**: either reclassify §9's regime to Range before building a fade-at-R1 card, or rebuild Trade
   2 as a breakout-side card consistent with "Transitional."

9. **Trade 3B (`2026-06-02_Trade_3B`) entry band is placed at the wrong percentile of the 25-day
   range.** M5 fixes the 3B short-fade entry zone at 78.6–88.6% of the 25-day range. Using the file
   (`swing_low_25d_full` = 4,366.35, `swing_high_25d_full` = 4,773.37, width = 407.02), that zone is
   4,686.25–4,726.95. The card's entry band is 4,535–4,560, which is only 41.4–47.6% of the range from
   the low — well below the specified fade zone. **Fix**: move the entry band into 4,686.25–4,726.95.
   TP1 "range mid" should also be corrected: the true midpoint is
   4,366.35 + 407.02/2 = 4,569.86, not the card's "≈4,480."

10. **Static linter integrity is not the same as market-relative construction integrity.**
    `lint_static/2026-06-02.csv` correctly shows all 3 cards CLEAN/0-DUD — the R-sizing, stop-side and
    TP-ordering checks it runs are all satisfied. Items 7–9 above are a different failure class (wrong
    *placement logic* relative to the regime/range rules) that a leak-free static linter cannot detect.
    Regeneration should not treat a CLEAN linter pass as confirmation that card construction is
    correct — it confirms only internal arithmetic, not rule selection.
