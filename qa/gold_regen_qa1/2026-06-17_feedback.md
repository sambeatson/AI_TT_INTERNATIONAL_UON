## Report-level defects

1. **Restriction breach — module code exposed in the report body.** §20 Agent Log reads: *"M5 trace:
   direction-score weights basis = DEFAULT (v2.1 baseline, weights locked, forward-test session 1)."*
   Module codes (M1–M5) must never appear by name in the report body. Remove "M5" (and any other module
   label) from anything that ships in the report; keep such notes only in an internal, non-shipped log.
   This alone triggers the restriction-breach override (caps the report at Moderate Trust and drops
   Category 1 at least one level).

2. **§2 as-of date field is wrong.** §2 states "As-of date/timezone: 17 June 2026 · Europe/London." The
   as-of session must be the last completed session strictly before the report date, i.e. **16 June 2026**
   — which is what every other section (§3, §4, §6, §19) actually anchors to. Correct the §2 field to
   16 June 2026 so it matches the rest of the report.

3. **Claimed futures corroboration is never evidenced.** The masthead states "GC=F corroboration," but no
   GC=F price appears anywhere in §4's Price Evidence Table, and no futures-to-spot normalisation size is
   stated in §4, §5 or §19. A compliant report must either (a) include the GC=F print actually used and
   state the contango subtracted (typically ~$10–25/oz per the QA protocol), or (b) remove the "GC=F
   corroboration" claim from the masthead if futures were not in fact used.

4. **ATR14 is never stated as a number.** It is used operationally (Trade 1's "3×ATR cap" runner rule; the
   general 0.25×ATR entry-buffer and 3.5×ATR stop-cap rules that govern all three cards) but no ATR14
   value appears anywhere in §9, §11 or §21. State it explicitly and say which basis it is: the level
   file's independently-derived 16-Jun values are **ATR14(full/continuous) = $117.28**, **ATR14(cash/US
   session) = $98.75**.

5. **§11 Daily pivot table shows 5 levels per side (R1–R5 / S1–S5); Weekly and Monthly tables correctly
   show 3 per side (R1–R3 / S1–S3).** Pick one convention and apply it consistently across all three
   pivot tables in the same report.

## Card-level defects

### Trade 1 (Daily Directional)
10. **Stop buffer is far tighter than the M5 rule requires.** Rule: stop = tighter of (5-day swing
    extreme, nearest S/R) **+ 0.25×ATR14 buffer**, capped at 3.5×ATR14. The card's own stated anchor is
    the 16-Jun low ($4,306.10). A compliant stop = $4,306.10 − 0.25×$117.28(ATR14 full) = **$4,276.78**
    (R ≥ ~$63.22), or using ATR14(cash)=$98.75 → $4,281.43 (R ≥ ~$58.57). The card's actual stop is
    $4,303 — only a ~$3.10 buffer below the anchor, R=$37. Widen the stop (or clearly document a
    different, stated buffer rule) to satisfy the 0.25×ATR requirement.

### Trade 2 (Pivot, regime-aware)
11. **Entry/stop match none of the three regime-conditioned M5 formulas.** The report's own regime call
    (§9) is TRANSITION, for which M5 specifies Trade 2 = "breakout side only." The card instead rests a
    buy-limit exactly at the daily pivot ($4,331.90) — not a breakout order (TRANSITION), not a limit at
    S1/S1.5/S2 (RANGE: S1=$4,314.20/S1.5≈$4,306/S2=$4,288.40), and not the TREND formula entry =
    P + 0.10×(R1−P) = $4,331.90 + 0.10×($4,357.70−$4,331.90) = **$4,334.48**. State which regime-conditioned
    formula governs this card and rebuild entry and stop to match it exactly.

### Trade 3A (Regime-driven, momentum-pullback fork)
12. **Entry methodology does not match the M5 3A specification.** M5 3A is a 57.5%-retracement pullback
    entry into a qualifying logged swing (magnitude ≥ 2×ATR14, 4–10 session lookback, endpoints logged),
    stop beyond the 0% swing anchor by 0.25×ATR14, TP1 at 38.2%, TP2 at 0%, TP3 at 100%+ extension. The
    card instead uses a stop-entry breakout above the 16-Jun high ($4,349.60) — a different construction
    entirely, with no swing endpoints logged. Rebuild against the specified swing: log its 0%/100%
    endpoints, enter at the 57.5% retracement level, and set the stop at (0% anchor) ∓ 0.25×ATR14.
13. **TP2 mislabelled.** TP2 = $4,425 is labelled "≈+2.3R / range measured-move," but $4,425 − $4,351 =
    $74 = exactly **+2.00R** against the card's own stated R of $37. Fix the label (or the level, if 2.3R
    was actually intended).
14. **TP3 given as a band, not a single price.** "$4,451–$4,488 (daily R4/R5)" does not fit a single-TP3
    schema; either commit to one runner target or split into a labelled TP3a/TP3b if the card schema
    supports it.
