# Feedback — Gold_Report_03-Jul-2026.md (run gold_regen_qa1)

Numbered, actionable defects only. Numbers below are taken from `data/levels/XAUUSD_by_date/2026-07-03.csv`
(leak-free, `last_bar_date=2026-07-02 < 2026-07-03`) and from the report's own stated figures. No claim is
made about what price did on or after 03 Jul 2026.

## Report-level defects

1. **Fabricated/self-contradictory source citation — §4 vs §8/§11/§16/§21b (triggers the hallucinated-source
   override, Category 3 = 0).** §4's Price Evidence Table attributes to FXStreet (02 Jul) a 20-day SMA of
   "~$4,034". Five other places in the same report (§8 "structural $4,183 (20-day SMA per FXStreet)"; §11
   position narrative; §16 "$4,183 (20-day SMA)"; the Trade 3A entry rationale; the Trade 3A TP3/confluence
   row) use **$4,183** for the identical figure from the identical source. A cited source's own figure must
   be used consistently wherever it recurs (framework 3.2/3.4). Fix: verify FXStreet's actual 02 Jul 20-day
   SMA reading and use one number everywhere it is cited, or, if $4,034 and $4,183 are genuinely two
   different reference levels, rename them so they are not both labelled "20-day SMA per FXStreet."

2. **Daily pivots computed from the wrong session — §11.** The header states "Daily pivots (from 01 Jul
   H/L/C)"; reproducing the floor-pivot formula on 01 Jul's own H=4,045.00/L=3,951.68/C=4,031.29 gives
   P=(4,045.00+3,951.68+4,031.29)/3=**4,009.32**, exactly matching the printed table — confirming 01 Jul
   (D−2) was used instead of 02 Jul (D−1), which is the report's own last-completed session per §2. A
   compliant daily pivot must be computed from the 02 Jul H/L/C the report itself already prints in §6
   (4,144.11 / 4,030.81 / 4,108.07). Against the leak-free level file, the printed P (4,009.32) misses the
   correct D−1-based pivot (`d_full_P`=4,099.4833) by 90.16 points = 0.79×ATR14 — a Category 3 failure by a
   wide margin, and it silently propagates a full session's staleness into every Trade 2 level, since Trade
   2's TP3 is explicitly "runner exit at P per Trade-2 rule."

3. **02 Jul close outside tolerance — §6/§11 vs level file.** Report's D−1 close = 4,108.07;
   `prev_close_full` = 4,123.79. Delta = 15.72 = 0.1375×ATR14 (`atr14_full`=114.3221), above the
   0.115×ATR14 (≈$13.15) Category-3 failure threshold (O/H/L for the same session are all within
   tolerance). A compliant D−1 close for this basis must sit within ±$4.57 (0.04×ATR14) to be flagged
   "consistent," and within ±$13.15 to avoid a Category 3 failure.

4. **Weekly and monthly pivots also outside tolerance — §11 vs level file.** Period selection is correct
   for both (weekly: last completed week 22–26 Jun, matching `w_full_period`=2026-W26; monthly: June,
   matching `m_full_period`=2026-06), but the levels themselves miss: weekly P 4,037.44 vs `w_full_P`
   4,086.99 (Δ49.55 = 0.43×ATR14); monthly P 4,238.39 vs `m_full_P` 4,165.5133 (Δ72.88 = 0.64×ATR14). Both
   exceed the 0.115×ATR14 failure threshold for a pivot level. Re-derive both from higher-fidelity
   prior-period H/L/C, or, if the source data genuinely differs from the broker feed, flag the delta
   explicitly rather than presenting the pivots as ordinary single-source-indicative values.

5. **Unrendered template artifact — §9.** The line "Kaufman confirmation: KER = {S['ker_value']:.2f} →
   Trending Down — Moderate (|KER| > 0.13)" is a raw, unsubstituted code fragment, not the number. The
   value (-0.22) is only recoverable because it happens to be repeated in §1 and §21a. Fix: render the
   actual KER value in §9 itself; this is also a 5.4 restriction concern (a bracketed internal variable
   reference should never reach the report body).

6. **Pivot table format does not match the M4 structure spec — §11.** All three pivot tables (daily,
   weekly, monthly) print 5 levels per side (R5…P…S5, 11 rows) instead of the specified 3 levels per side
   (R3→P→S3, 7 rows). Trim each table to R3/R2/R1/P/S1/S2/S3.

7. **Daily-open anchor override not carried to the cards or into §21b — §20 vs §21b.** §20 records an
   override of the default 00:00 UK anchor to 23:00 UK, and frames it correctly as a logged
   non-conformance rather than presenting it as the instance anchor — that part is compliant. But the
   module requires the same converted time to also appear "on the card" and "in the report body"; neither
   Trade 2 nor Trade 3A states any clock time at all. Add the converted anchor time (and the override flag)
   to both live cards in §21b.

## Per-card defects

**Trade 2 — Pivot / range-fade (SHORT, live)**
8. Entry cell states "$4,145.00 ... ~3,700 ticks above daily P." At the card's own $0.01 tick, the actual
   distance from $4,145.00 to the stated P ($4,009.32) is (4,145.00−4,009.32)/0.01 = **13,568 ticks**, not
   ~3,700 — an arithmetic error of roughly 3.7×. (The R and TP tick counts elsewhere on the same card,
   3,800/7,600, are internally correct — only this one figure is wrong.) Correct the tick count or drop it.
9. Because the daily P this card's TP3 targets is itself wrong (defect 2 above: computed from 01 Jul, not
   02 Jul), TP3 ($4,009.32) must be recomputed once the pivot table is corrected — it should instead target
   `d_full_P`-derived value once daily P is fixed to 4,099.4833 (≈+90 vs current TP3).

**Trade 3A — Momentum-Pullback (LONG, live)**
10. The reference swing (01 Jul low $3,951.68 → 02 Jul high $4,144.11) is ~1–2 sessions old, short of the
    M5 rule's required 4–10 session lookback for a "qualifying swing." Select a swing whose endpoints are
    4–10 sessions apart.
11. That same swing's magnitude is $192.43, below the required ≥2×ATR14 = $228.64
    (2×114.3221) — it does not qualify as a Trade-3A swing under the module rule regardless of lookback.
    A compliant swing on this date must span ≥ $228.64.
12. Entry is stated as "$4,072.00 — 38.2% retrace of the 01 Jul low→02 Jul high leg," but the rule requires
    entry at the **57.5%** retracement. Reproducing 38.2% from this leg gives
    4,144.11−0.382×(4,144.11−3,951.68)=**$4,070.60**, matching the stated entry almost exactly — confirming
    38.2% was used where 57.5% is required. The compliant entry on this leg would be
    4,144.11−0.575×(4,144.11−3,951.68)=**$4,033.46**, roughly $39 below the entry printed.
13. TP1 is separately labelled "38.2% target," the same percentage already (mis)used for the entry — the
    card cannot self-consistently place two different price levels at the same retracement percentage of
    the same leg. Re-derive so entry = 57.5%, TP1 = 38.2%, TP2 = 0% (swing origin), TP3 = 100%+ extension,
    per the rule.
14. Stop is "$4,030.00 — below the 02 Jul low $4,030.81," but the rule requires the stop "beyond the 0%
    anchor by 0.25×ATR" — the 0% anchor for this swing is the 01 Jul low ($3,951.68), not the unrelated 02
    Jul low. A compliant stop is 3,951.68 − 0.25×114.3221 = **$3,923.10**, roughly $107 below the stop
    printed. Recompute entry, stop and R once the correct swing/anchor are used; TP1/TP2/TP3 and the R-based
    tranche management all follow from that recomputation.
