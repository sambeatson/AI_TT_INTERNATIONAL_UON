   (22–26 Jun)" — ISO week 26 — but the correct prior-completed-week for a 6 Jul (Monday) report is
   29 Jun–3 Jul (ISO week 27), which is exactly the week the report's own §6 five-day table already
   covers (H 4,195.56 / L 3,944.23 / C 4,180.06 across that table's rows). Rebuild §11's weekly pivots
   from that week's H/L/C. Using the level file as the target: P should be ≈4,104.46 (report gives
   4,089.82, off by $14.64), R1 ≈4,265.85 (report gives 4,220.26, off by $45.59), S1 ≈4,013.59 (report
   gives 3,958.82, off by $54.77), S2 ≈3,852.20 (report gives 3,828.38, off by $23.82) — all exceed the
   0.115×ATR14 tolerance for a pivot level (ATR14_full = 108.7257, so the failure threshold is ≈$12.5).
   This error is not cosmetic: it propagates into §16's stated base-case invalidation ("a daily close
   back below weekly P 4,090") and into Trade 1's card-level thesis invalidation ("Daily close below
   weekly P 4,090"), both of which should read closer to weekly P ≈4,104–4,107, not 4,090.

2. **§11's weekly and monthly pivots are not rendered as tables**, unlike the daily pivot table, and
   each gives only R1/R2/S1/S2 — the R3/S3 outer band is missing for both. Bring weekly and monthly
   into the same table format as daily, with all three levels each side (R3→P→S3 at minimum, matching
   the format the daily table already uses).

   to the same June high figure — re-verify the true 25-day/June high before the next run; if 4,545.87
   is correct, Trade 3C's TP3 runner target and range width both need updating.
