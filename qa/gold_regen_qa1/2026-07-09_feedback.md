# Feedback — Gold_Report_09Jul2026.md (XAUUSD, D = 2026-07-09)

Numbered, specific, actionable. Numbers are drawn from `data/levels/XAUUSD_by_date/2026-07-09.csv`
(leak-free, `last_bar_date` 2026-07-08 < D). No statement below concerns price on or after D.

## Report-level defects

1. **D−1 (08 Jul) close and low are materially wrong, and everything computed from them inherits the
   error.** Report's §6 states 08 Jul close = $4,125.28, low = $4,096.55. The leak-free level file
   gives `prev_close_full` = **$4,077.47** (diff $47.81 ≈ **0.46×ATR14**, far past the 0.115×ATR
   ≈ $12 Category-3 failure line) and `prev_low_full` = **$4,021.75** (diff $74.80 ≈ **0.72×ATR**, also
   past the 0.20×ATR failure line for O/H/L). By contrast, High ($4,134.05 vs file $4,134.01, diff
   $0.04) and Open ($4,098.58 vs file $4,094.61, diff $3.97) both reconcile cleanly against the `_full`
   basis. Fix: rebuild §1/§3/§4/§6's 08 Jul close and low from the file's `_full` OHLC
   (O=4,094.61 H=4,134.01 L=4,021.75 C=4,077.47) — the session was a wide down-day into the close, not
   the "76.6%-of-range bullish recovery" the report describes.

2. **RSI2 (28.7) fails the external tolerance, even though it reproduces from the report's own (wrong)
   closes.** Recomputing RS = mean-gain/mean-loss over the report's own stated last-2 changes gives
   ≈28.6 — internally transparent. But the level file's `rsi2_full`/`rsi2_cash` = **0.0**, a diff of
   **28.7 points**, exceeding the >15-point Category-3 failure line. This is a direct consequence of
   defect 1: the correct 08 Jul close (4,077.47) is *below* the 07 Jul close, making 08 Jul a second
   consecutive loss day (RS=0 ⇒ RSI2=0), not a recovery day. Fix: recompute RSI2 from the corrected
   5-day close sequence ending 4,077.47.

3. **All three daily pivots the report presents as tradeable levels fail reconciliation**, because they
   are computed from the wrong 08 Jul close (defect 1). Compliant daily pivots from the file's `_full`
   H/L/C (4,134.01 / 4,021.75 / 4,077.47) are: P=4,077.74, R1=4,133.74, R2=4,190.00, R3=4,246.00,
   S1=4,021.48, S2=3,965.48, S3=3,909.22. Report's stated values (P=4,118.63, R1=4,140.70, R2=4,156.13,
   R3=4,178.20, S1=4,103.20, S2=4,081.13, S3=4,065.70) differ from these by $40.89 / $6.96 / −$33.87 /
   −$67.80 / $81.72 / $115.65 / $156.48 respectively — S1, S2, S3, R2 and R3 all exceed the
   0.115×ATR14 (≈$12) failure threshold. By contrast, **the weekly pivot table (built from the prior
   week 29 Jun–03 Jul) reconciles almost exactly against `w_full`** (all six levels within 0.02×ATR) —
   the weekly build is sound; only the daily build, propagated from the wrong 08 Jul close, is broken.
   Fix: rebuild §11's daily pivot table from the corrected 08 Jul H/L/C in defect 1, and rebuild
   Trade 1/Trade 2's entries, stops and TPs (all keyed to daily S1/S3/R1/R3 confluence) from the
   corrected table.

4. **§11's three pivot tables show R5→S5 (5 levels/side, 11 rows) instead of the specified R3→P→S3
   (3 levels/side).** This applies to the daily, weekly, and monthly tables alike. Fix: trim each table
   to R3, R2, R1, P, S1, S2, S3 only.

5. **§7 "Charts" has five bare headings and zero caption or placeholder text under any of them.** The
   review protocol accepts a caption or placeholder as evidence when the docx→md conversion drops the
   images themselves, but this report supplies neither for any of the 5 toggled chart types
   (Candlestick / Distance-From-Open / 25-Session Structure / VOLator / Pivot Structure). Fix: add one
   caption/placeholder line per chart (e.g. what the chart shows and its key readout).

6. **AS_OF_DATE (§2) is set to the report date (09 Jul 2026) instead of D−1.** `M1_Variables_v2_1.md`
   fixes AS_OF_DATE to "the last completed regular session... that closed strictly before the report
   date," which for D = 2026-07-09 is **2026-07-08**. The body itself does not leak D as settled data
   (§6's last row and §21c's backtest both correctly stop at 08 Jul) — this is a labelling error, not a
   data leak — but the field itself is wrong and should be fixed to 08 July 2026.

7. **Consensus price build does not actually use the required ≥6 independent sources.** §4 lists 6
   rows, but §5 states explicitly that only Investing.com (spot) and CME GC=F (futures, corroboration
   only) are treated as "Core"; the other four (TradingEconomics, TradingView, MQL5, LiteFinance/OCBC)
   are described as representing "the session trough, not the settled close" and are not blended into
   the $4,125/oz figure. `M1_Variables_v2_1.md` §C fixes MINIMUM_SOURCE_COUNT = 6 "for consensus price
   build." Fix: either blend enough independent spot sources into the weighted-median consensus to
   genuinely reach 6, or state explicitly why the fixed minimum was relaxed for this run.

8. **The daily-open-anchor departure is not logged as the module's required non-conformance.** §20
   states the anchor was "overridden to 00:00 UK per run instruction," but never states what the
   populated instance's anchor value actually was, and §2's Market Definition table presents "00:00 UK"
   as a plain fact ("Daily-open anchor | 00:00 UK") rather than as a flagged departure. Per
   `M1_Variables_v2_1.md`, a departure "is a logged non-conformance, not an anchor... never presented as
   the instance's anchor value." Fix: state the populated anchor value being departed from, and label
   the 00:00 UK entry-time on §2, §20 and every card explicitly as a non-conformance rather than as the
   plain anchor.

9. **The futures-to-spot normalisation is described only qualitatively, with no stated size.** §5 and
   §19 describe a "contango premium" but never quantify it — unlike the expected disclosure of a
   specific normalisation size (the evidence table's own numbers imply roughly a $46–61 spread between
   the GC=F settle and the accepted spot close, but this is never stated as an applied adjustment). Fix:
   state the contango size actually applied (or observed) between the futures settle and the spot
   close.

## Per-card defects

10. **Trade 1 is built as a STOP order, not the M5-fixed "market at the daily-open anchor."** The card
    entry is "Sell stop at 4,103.00 on confirmed break of daily S1... (order placed at 00:00 UK
    anchor)" — a conditional stop order, not a market fill at the anchor time. The M5 rule for Trade 1
    fixes the entry mode as a market order at the daily-open anchor; entering only on a confirmed break
    is a different order type from what the rule specifies. Fix: reconstruct Trade 1 as a market entry
    at the anchor-time price (the corrected 08 Jul close from defect 1, i.e. $4,077.47, adjusted for the
    09 Jul open convention used elsewhere), with stop/TP1/TP2 rebuilt around that entry.

11. **Trade 1's runner cap ("3×ATR cap → ~4,006 floor") does not reconcile to any stated reference
    price.** 3×ATR14 from the stated entry (4,103.00) using the card's own "ATR14 ≈109" gives
    4,103.00 − 3×109 = **3,776.00**, not ~4,006. The figure does not reconcile from the stop (4,148.00)
    or the D−1 close either. Fix: show the derivation of the runner floor explicitly (which reference
    price × which ATR multiple), or correct the stated floor to match 3×ATR14 from the actual entry.

12. **Trade 2 (RANGE regime) is tiered at daily R3 instead of the M5-required R1/R1.5/R2 for a RANGE
    short.** The regime is explicitly "Ranging" in §9, and the M5 rule for a RANGE Trade 2 fixes the
    short-side entry tier to R1/R1.5/R2, not R3. The card enters at 4,178.00, explicitly anchored to
    "daily R3." Fix: retier the entry among R1 ($4,133.74), the midpoint R1.5, or R2 ($4,190.00) per
    the file's corrected daily pivots (defect 3), by distance in ATR as the rule specifies, rather than
    at R3.

13. **Trade 2's TP2 is not the fixed 2R the rule requires.** M5 fixes "TP1 = entry ± 1R, TP2 = entry ±
    2R for Trade 1 and RANGE Trade 2." With entry 4,178.00 and R = 37.00, TP2 must be 4,178.00 −
    2×37.00 = **4,104.00**. The card states TP2 = 4,119.00, only ≈1.59R away, not 2R. Fix: set TP2 to
    4,104.00 (or recompute both from the corrected entry per defect 12).

14. **Trade 3B's entry and TP1 use 5-day swing levels instead of the M5-required 25-day-range
    percentile zones.** The M5 3B rule fixes the short entry at **78.6–88.6% of the 25-day range** and
    TP1 at the **range mid**. Using the file's `swing_high_25d_full`/`swing_low_25d_full`
    (4,515.44 / 3,943.08, width $572.36): the compliant 78.6–88.6% short-entry zone is
    **$4,392.95–$4,450.19**, and the true range mid (TP1) is **$4,229.26** — both roughly $190–250 away
    from what the card actually uses. The card instead enters at "4,195–4,202" (the **5-day** swing-high
    band, `swing_high_5d_full` = 4,202.71) and sets TP1 "Range mid ≈ 4,118," which is in fact the
    daily/weekly/monthly pivot confluence, not the 25-day range midpoint. This is a different
    construction methodology from the one the rule specifies, not a numeric miss within it. Fix: rebuild
    Trade 3B's entry in the 78.6–88.6%-of-25-day-range zone (~$4,393–$4,450) with TP1 at the true range
    mid (~$4,229), and TP2 at 10%-of-width inside the far side (~$4,000, using
    `swing_low_25d_full` + 0.10×width) rather than the daily S2/S3 levels currently used.

15. **Trade 3B's stop distance (30 USD, entry 4,195 → stop 4,225) is far tighter than the M5 rule's
    "10% of width inside" sizing** — 10% of the (correctly-scoped) 25-day range width ($572.36) is
    $57.24, nearly double the $30 actually used. This compounds defect 14: once the entry zone is
    corrected, the stop should also be resized to 10% of the $572.36 width from the corrected entry, not
    the $30 currently used (which was sized off the 5-day swing instead).

16. **Trade 3B carries a linter WARN (`WARN_R_TINY(0.29xATR)`)** — R = 30.00 USD against ATR14_full =
    104.02 is 0.29×ATR, just under the 0.3×ATR minimum. This is consistent with, and a direct
    consequence of, the undersized stop in defect 15: once the stop is resized to the rule-compliant
    ~$57.24, R will clear the 0.3×ATR floor and the WARN should clear on regeneration.
