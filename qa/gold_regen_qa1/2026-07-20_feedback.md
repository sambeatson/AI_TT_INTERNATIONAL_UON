## Report-level defects

1. **Daily floor pivots are built from the wrong prior session (§11 Daily pivots).** The table header
   reads "prior session: Thu 16 Jul" and its levels (P=3,981.13, R1=4,003.95, S1=3,953.75, …) back-solve
   exactly from Thursday's own §6 row (H=4,008.50, L=3,958.30, C=3,976.58). But §2 and §20 both correctly
   state the as-of/last-completed session is **Fri 17 Jul**, and M4 §11 requires the daily pivot input to
   be "the completed session before the report date." Using the level file's leak-free Fri 17 Jul H/L/C
   (H=4,023.83, L=3,959.65, C=4,016.50, `_full` basis): P=3,999.9933, R1=4,040.3367, S1=3,976.1567,
   R2=4,064.1733, S2=3,935.8133, R3=4,104.5167, S3=3,911.9767. Every report level misses by 18.9–36.4
   USD/oz, all far past the 11.17 USD/oz (0.115×ATR14_full) Category-3 failure ceiling. This error
   propagates into Trade 1's stated confluences ("daily R1 4,003.95") and into §11's own position
   narrative.
2. **Weekly floor pivots are built from the wrong prior week (§11 Weekly pivots).** The table header
   reads "prior week to 10 Jul" (ISO week 28), but the last fully completed calendar week before D
   (20 Jul, a Monday) is **13–17 Jul** — the same week the report's own §6 table covers, and it matches
   the level file's `w_full_period = 2026-W29`. Leak-free weekly pivots (`_full` basis): P=4,026.44,
   R1=4,093.23, S1=3,949.71, R2=4,169.96, S2=3,882.92, R3=4,236.75, S3=3,806.19. The report's

   0.115×ATR14 failure ceiling. This wrong weekly P is then repeated as the invalidation trigger in
   Trade 1's card, §16's base-case invalidation, §17's forecast sentence, and §18's judgement — every
   one of those references needs restating to weekly P ≈ 4,026.4 (full) / 4,026.6 (cash).
3. **Monthly floor pivots use the correct period but the wrong levels (§11 Monthly pivots).** The period

## Card-level defects

9. **Trade 1 (SHORT) — ATR(14) used for the stop buffer is wrong, and the resulting R is below the
   floor the module's own pre-emit check requires (linter: `WARN_R_TINY(0.19xATR)`).** The card computes
   its stop as nearest-resistance (4,020.10) + 0.25 × ATR(14)=60.80 = 4,035.30, giving R=17.98. Using the
   leak-free `atr14_full`=97.1236 instead, the buffer is 0.25 × 97.1236 = 24.28, so a compliant stop
   built on the same structural anchor would sit at 4,020.10 + 24.28 = 4,044.38, giving R=27.06 (still
   only 0.279×ATR14 — below the 0.3×ATR14 minimum the module's own §9a check 6 requires before a card
   may be emitted rather than rebuilt). Because the 5-day nearest resistance (4,020.10) is too close to
   entry (4,017.32) to produce a compliant R even with the correct ATR, this card should either use a
   materially wider structural anchor (e.g. `swing_high_5d_full`=4,103.17, per M5 §4c's "tighter of
   swing extreme or nearest resistance" rule — here the swing extreme, not the resistance, would need to
   be the binding anchor) or be rebuilt from scratch, not shipped with the WARN_R_TINY flag standing.
