## Report-level data defects

1. **Daily pivots are built from the wrong prior session.** §11 states "Daily pivots (from 27 Jul
   H/L/C)". For a 29 Jul report, D-1 is Tue 28 Jul — the report's own §6 table already has that row
   (O 4,047.65 / H 4,082.45 / L 4,021.56 / C 4,030.00). Rule violated: floor pivots must use the
   immediately preceding completed session's H/L/C. A compliant daily P must be computed from Tue 28
   Jul's H/L/C (giving P ≈ (4,082.45+4,021.56+4,030.00)/3 ≈ $4,044.67, which is within the consistent
   band of the level file's `d_full_P` $4,040.67), not from Monday's, which produced P $4,071.12 —
   $30.45 from `d_full_P`, more than 3x the $9.45 Category-3 failure threshold (0.115×`atr14_full`
   82.1414). This single date error propagates into every daily R/S level quoted in §11 and into
   Trade 1's confluence text ("daily R1 $4,096").

2. **Weekly pivots fail reconciliation.** §11's weekly P/R1/S1 ($4,036.27 / $4,106.13 / $3,982.03)
   diverge from the level file's `w_full_P` $4,067.44 (Δ$31.17), `w_full_R1` $4,152.10 (Δ$45.97) and
   `w_full_S1` $3,968.81 (Δ$13.22) — all beyond the $9.45 failure threshold. A compliant weekly S1
   must sit within 0.115×ATR14 of $3,968.81, i.e. in [$3,959.36, $3,978.26]; the card's actual trigger
   basis, $3,982.03, is outside that band. This matters because weekly S1 is the literal Trade 2 entry
   trigger (§21b: "Sell-stop on confirmed break of weekly S1 $3,982").

3. **Monthly pivots fail reconciliation.** §11's monthly P/R1/S1 ($4,111 / $4,279 / $3,841) diverge
   from `m_full_P` $4,165.51 (Δ$54.51), `m_full_R1` $4,387.95 (Δ$108.95) and `m_full_S1` $3,785.16
   (Δ$55.84) — all far beyond the $9.45 failure threshold. A compliant monthly P must sit within

4. **Tue 28 Jul Open fails reconciliation.** §6 states Open $4,047.65. `prev_open_full` is $4,081.18
